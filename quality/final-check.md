# QUALITY GATE 3 — FINAL CHECK (البوابة النهائية)

آخر 60 ثانية قبل تسليم أي رد — للرد الأول وللحزمة النهائية معًا.

## للرد الأول (Discovery)

- [ ] إعادة الصياغة موجودة وقوية ودون تقنية.
- [ ] 3 أفكار بالضبط — كل واحدة باسم + مفاجأة.
- [ ] 3 أسئلة بالضبط — كل واحدة مع افتراض مقترح.
- [ ] صفر تسريب داخلي (لا مراحل، لا وكلاء، لا "سأحلل").
- [ ] صفر برومبتات في هذا الرد.
- [ ] اللهجة قريبة من المستخدم والمجمعة في 30 ثانية قراءة.

## للحزمة النهائية

### الشكل
- [ ] كل برومبت داخل code block مستقل قابل للنسخ.
- [ ] الأبعاد خارج الكود، وتعليمات الرفع موسومة (⬆️/📋).
- [ ] الترتيب: افتتاح → مرجع (إن لزم) → لقطات → مشاهد → دليل → ملاحظات مونتاج.
- [ ] لا شيء داخلي ظاهر (أسماء وكلاء، INTERNAL، VISUAL DNA كجملة ظاهرة، SHOT LIST كمصطلح).

### المحتوى
- [ ] مرت الحزمتان السابقتان (product-fidelity + consistency) بعلامة كاملة.
- [ ] كل برومبت نجح اختبار العشرة ثوانٍ من `frameworks/prompt-architecture.md`.
- [ ] لا نصوص مطلوبة داخل الصور (أو تحذير مرفق بطلب المستخدم).
- [ ] المشاهد تغطي المدة كاملة بلا فجوات.
- [ ] الحزمة القياسية: 1 مرجع + 4–8 لقطات + 4–8 مشاهد (أو حسب حجم الطلب).

### الدليل
- [ ] 5–8 خطوات تنفيذية مرقمة.
- [ ] يحتوي سطري الحماية: "ما يدعم رفع صور" + "أعد التوليد عند كسر المنتج".
- [ ] ملاحظة مونتاج وصوت موجودة وقصيرة.
- [ ] سطر الافتراضات في المطلع (إن وُجدت افتراضات).

### اللسان
- [ ] لغة المستخدم نفسها، دافئة وواثقة.
- [ ] لا اعتذارات، لا تردد، لا "يمكن أن"، لا حشو افتتاحي.
- [ ] الرد يُقرأ كدليل تشغيل نهائي — المستخدم لا يحتاج أن يسأل شيئًا بعدده.

## الحكم النهائي

كل البنود ✔ → سلّم الحزمة فورًا.
أي بند ✘ → أصلح داخليًا ثم أعد الفحص. **لا يُسلَّم شيء ناقص أبدًا — ولا يُعلَق شيء على المستخدم.**
